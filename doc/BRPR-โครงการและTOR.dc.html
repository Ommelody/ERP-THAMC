เอกสารประกอบโครงการ — ประจำปีงบประมาณ 2568

โครงการพัฒนาระบบเสนอขออนุมัติจัดสรรงบประมาณ
และติดตามสถานะการจัดซื้อ (BRPR)

ศูนย์การแพทย์ธรรมศาสตร์ โรงพยาบาลธรรมศาสตร์เฉลิมพระเกียรติ

๑. ชื่อโครงการ

โครงการพัฒนาระบบเสนอขออนุมัติจัดสรรงบประมาณและติดตามสถานะการจัดซื้อ (Budget Request & Purchase Request System : BRPR)

๒. ผู้รับผิดชอบโครงการ

ผู้รับผิดชอบ : นายสวรินทร์ ศรีเกษ

ตำแหน่ง : นักตรวจสอบภายใน ปฏิบัติหน้าที่นักวิชาการพัสดุ

๓. หลักการและเหตุผล

ปัจจุบันกระบวนการเสนอขออนุมัติจัดสรรงบประมาณและการเสนอความต้องการจัดซื้อจัดจ้าง (Purchase Requisition) ของศูนย์การแพทย์ธรรมศาสตร์ ยังคงอยู่ในรูปแบบการใช้เอกสารกระดาษเป็นหลัก ก่อให้เกิดปัญหาและความเสี่ยงหลายประการ การส่งเอกสารระหว่างหน่วยงานเพื่อขออนุมัติตามสายงานบังคับบัญชาเกิดความล่าช้า ทำให้กระบวนการจัดซื้อจัดจ้างโดยรวมไม่ทันต่อความต้องการใช้งานที่เร่งด่วน อีกทั้งการควบคุมยอดงบประมาณคงเหลือยังกระจายอยู่หลายแหล่ง เสี่ยงต่อการจัดสรรงบซ้ำซ้อนหรือเกินกรอบวงเงิน นอกจากนี้การใช้เอกสารกระดาษยังสิ้นเปลืองทรัพยากรในการพิมพ์และจัดเก็บ มีความเสี่ยงที่เอกสารจะสูญหายหรือชำรุดระหว่างขั้นตอน และทำให้การติดตามสถานะของคำขอเป็นไปได้ยาก

ดังนั้น เพื่อแก้ไขปัญหาดังกล่าวและเพิ่มประสิทธิภาพการดำเนินงานขององค์กร จึงได้พัฒนาระบบ “BRPR” ในรูปแบบ Web Application ขึ้น เพื่อเปลี่ยนกระบวนการขออนุมัติงบประมาณและการขอซื้อแบบเดิมให้เป็นระบบดิจิทัลอย่างเต็มรูปแบบ ครอบคลุมตั้งแต่การเสนอขออนุมัติจัดสรรงบประมาณ การอนุมัติและตัดยอดงบ การเสนอความต้องการซื้อ ไปจนถึงการติดตามสถานะการจัดซื้อ การตรวจรับ และการเบิกจ่าย โดยทำงานควบคู่กับข้อมูลจากระบบ SAP ขององค์กร ซึ่งจะช่วยลดขั้นตอน ลดระยะเวลา ลดการใช้กระดาษ ติดตามสถานะได้แบบเรียลไทม์ เพิ่มความโปร่งใสและง่ายต่อการตรวจสอบ ทั้งยังเป็นการสร้างฐานข้อมูลการจัดซื้อจัดจ้างที่เป็นระบบเพื่อนำไปใช้ประโยชน์ในการวางแผนและบริหารจัดการต่อไป

๔. วัตถุประสงค์

  1. เพื่อพัฒนาระบบดิจิทัล (BRPR) ทดแทนกระบวนการเสนอขออนุมัติจัดสรรงบประมาณและการเสนอความต้องการจัดซื้อจัดจ้างรูปแบบเดิมที่เป็นกระดาษ
  2. เพื่อลดขั้นตอนและระยะเวลาในกระบวนการขออนุมัติจัดสรรงบประมาณและการจัดซื้อจัดจ้าง
  3. เพื่อเพิ่มประสิทธิภาพในการควบคุมงบประมาณ ป้องกันการจัดสรรงบซ้ำซ้อนหรือเกินกรอบวงเงิน
  4. เพื่อเพิ่มความสะดวกในการติดตามสถานะของคำขออนุมัติงบ (BR) และใบเสนอขอซื้อ (PR) แบบเรียลไทม์
  5. เพื่อสร้างระบบฐานข้อมูลการจัดซื้อจัดจ้างที่ตรวจสอบและนำไปวิเคราะห์เพื่อการบริหารจัดการได้

๕. วิสัยทัศน์ พันธกิจ ค่านิยม THAM-C

โครงการนี้สนับสนุนค่านิยม THAM-C ผ่านการนำเทคโนโลยีสมัยใหม่มาปรับปรุงกระบวนการทำงานภายใน โดยพัฒนา Web Application ด้วยเทคโนโลยีมาตรฐานสากล (React และ Backend-as-a-Service บนฐานข้อมูล PostgreSQL) เพื่อแก้ปัญหาที่เกิดขึ้นจริง สะท้อนถึงการมุ่งเน้นนวัตกรรมและประสิทธิภาพ ซึ่งสอดคล้องกับพันธกิจในการพัฒนาระบบบริหารจัดการที่เป็นเลิศ และค่านิยมขององค์กรที่มุ่งมั่นพัฒนาอย่างไม่หยุดนิ่ง เพื่อยกระดับการให้บริการและการปฏิบัติงานในทุกมิติ

๖. วิธีดำเนินการ

ออกแบบและพัฒนาระบบในรูปแบบ Web Application (Single Page Application) ที่รองรับการติดตั้งเป็นแอปพลิเคชันบนอุปกรณ์ (PWA) โดยใช้เทคโนโลยีดังนี้

  • ส่วนหน้า (Frontend) : พัฒนาด้วย React ทำงานผ่านเว็บเบราว์เซอร์ ไม่ต้องติดตั้งโปรแกรมเพิ่มเติม รองรับการใช้งานทั้งบนคอมพิวเตอร์และอุปกรณ์เคลื่อนที่
  • ส่วนหลัง (Backend) : ใช้บริการ Backend-as-a-Service (BaaS) บนฐานข้อมูล PostgreSQL สำหรับจัดเก็บข้อมูลรวมศูนย์ พร้อมระบบยืนยันตัวตนและการควบคุมสิทธิ์ในตัว
  • การเชื่อมโยงข้อมูล : นำเข้าข้อมูลจากระบบ SAP (ใบสั่งซื้อ การตรวจรับ การตั้งหนี้ การจ่ายเงิน และงบประมาณ) เพื่อทำงานควบคู่และกระทบยอดสถานะอัตโนมัติ

๘. ตัวชี้วัด (KPIs)

ตัวชี้วัดค่าเป้าหมายวิธีการวัดระยะเวลาการวัด
จำนวนคำขออนุมัติงบ (BR) และใบขอซื้อ (PR) ที่ดำเนินการผ่านระบบ BRPR เทียบกับจำนวนทั้งหมด100%ตรวจสอบจำนวนเอกสารที่สร้างผ่านระบบ เทียบกับจำนวนทั้งหมดที่เกิดขึ้นในศูนย์การแพทย์3 เดือนแรกหลังเริ่มใช้งานจริง
จำนวนคำขอที่ต้องส่งคืนเพื่อแก้ไขข้อมูลลดลง< 30%เทียบจำนวนคำขอที่ถูกตีกลับในระบบ BRPR กับจำนวนที่เคยถูกตีกลับในกระบวนการแบบกระดาษ3 เดือนแรกหลังเริ่มใช้งานจริง
ความพึงพอใจของผู้ใช้งานระบบ> 80%แบบสอบถามความพึงพอใจของผู้ใช้งานระบบ BRPR3 เดือนแรกหลังเริ่มใช้งานจริง

๑. ความเป็นมา

ศูนย์การแพทย์ธรรมศาสตร์มีความประสงค์จะพัฒนาระบบสารสนเทศเพื่อทดแทนกระบวนการเสนอขออนุมัติจัดสรรงบประมาณและการเสนอความต้องการจัดซื้อจัดจ้างที่ใช้เอกสารกระดาษ ให้เป็นระบบดิจิทัลที่ควบคุมงบประมาณ ติดตามสถานะ และตรวจสอบย้อนหลังได้ โดยทำงานควบคู่กับข้อมูลจากระบบ SAP ขององค์กร จึงกำหนดขอบเขตของงาน (TOR) สำหรับการพัฒนาระบบไว้ดังนี้

๒. วัตถุประสงค์ของการจัดทำ TOR

  1. เพื่อกำหนดขอบเขตงาน คุณสมบัติ และเงื่อนไขการพัฒนาระบบให้ชัดเจน
  2. เพื่อใช้เป็นเกณฑ์ในการตรวจรับงานและวัดผลความสำเร็จของโครงการ
  3. เพื่อให้ระบบที่พัฒนาตอบสนองความต้องการใช้งานจริงและมาตรฐานความปลอดภัยของข้อมูล

๓. ขอบเขตงานที่ต้องดำเนินการ (Scope of Work)

๓.๑ โมดูลเสนอขออนุมัติจัดสรรงบประมาณ (Budget Request : BR)

  • สร้างคำขออนุมัติงบ ระบุรายการ จำนวน ราคา หน่วยงาน เหตุผลความจำเป็น และวันที่ต้องการใช้งาน
  • ระบบออกเลขที่เอกสารอัตโนมัติแบบไม่ซ้ำ (รองรับการใช้งานพร้อมกันหลายคน)
  • สายทางการอนุมัติตามลำดับ พร้อมการตีกลับเพื่อแก้ไขและบันทึกเหตุผล
  • ตรวจสอบและตัดยอดงบประมาณคงเหลือแบบอัตโนมัติในธุรกรรมเดียว ป้องกันการจัดสรรซ้ำซ้อนและยอดงบติดลบ
  • ออกรหัสพัสดุประกอบการจัดสรรงบ

๓.๒ โมดูลใบขอซื้อและติดตามการจัดซื้อ (Purchase Request : PR)

  • แปลงคำขอที่ได้รับจัดสรรงบเป็นใบขอซื้อ พร้อมรายละเอียดสินค้า ผู้ขาย และเงื่อนไข
  • ติดตามสถานะตามขั้นตอน: ขออนุมัติงบประมาณ → เสนอความต้องการซื้อ → ติดตามการจัดซื้อ → ติดตามการตรวจรับ → ติดตามการเบิกจ่าย
  • ผูกเลขที่ใบสั่งซื้อ (PO) และค้นหารหัสพัสดุกลางแบบเรียลไทม์

๓.๓ การเชื่อมโยงข้อมูลกับระบบ SAP

  • นำเข้าข้อมูล SAP (ใบสั่งซื้อ การตรวจรับ การตั้งหนี้ การจ่ายเงิน และงบประมาณ)
  • กระทบยอดสถานะการจัดซื้อและการจ่ายเงินกับข้อมูล SAP อัตโนมัติ
  • รองรับการแยกข้อมูลงบประมาณตามปีงบประมาณราชการ (เริ่ม 1 ตุลาคม)

๓.๔ การจัดการผู้ใช้และความปลอดภัย

  • รองรับผู้ใช้ตามบทบาท ได้แก่ ผู้ขอ เจ้าหน้าที่งบประมาณ ผู้บริหาร จัดซื้อ การเงิน และผู้ดูแลระบบ
  • ควบคุมสิทธิ์การเข้าถึงข้อมูลตามบทบาทที่ระดับฐานข้อมูล
  • ยืนยันตัวตนด้วยอีเมลและรหัสผ่านที่เข้ารหัส และบันทึกประวัติการดำเนินการทุกขั้นตอน (Audit Log)

๔. คุณสมบัติทางเทคนิค

รายการข้อกำหนด
ส่วนหน้า (Frontend)Web Application (React, Single Page Application) รองรับการติดตั้งเป็น PWA และแสดงผลได้ทั้งคอมพิวเตอร์และอุปกรณ์เคลื่อนที่
ส่วนหลัง (Backend)Backend-as-a-Service บนฐานข้อมูล PostgreSQL รวมศูนย์ข้อมูลแบบเรียลไทม์
ความปลอดภัยระบบยืนยันตัวตนมาตรฐาน ควบคุมสิทธิ์ระดับแถวข้อมูล (Row Level Security) และบันทึก Audit Log
การเชื่อมโยงนำเข้าข้อมูลจากระบบ SAP เพื่อทำงานควบคู่และกระทบยอดสถานะ
การติดตั้งรองรับการติดตั้งบนบริการคลาวด์ และสามารถย้ายไปติดตั้งบนเซิร์ฟเวอร์ขององค์กร (Self-hosted) ได้

๕. ระยะเวลาดำเนินการและการส่งมอบ

ระยะเวลาดำเนินการรวม 12 เดือน (1 ตุลาคม 2568 – 30 กันยายน 2569) โดยแบ่งการส่งมอบงานเป็นงวด ดังนี้

งวดที่รายการส่งมอบกำหนดส่งมอบ
1เอกสารวิเคราะห์ความต้องการ และแบบร่างระบบ (UI/UX + โครงสร้างฐานข้อมูล)เดือนที่ 2
2ระบบต้นแบบพร้อมโมดูลงบประมาณ (BR) และใบขอซื้อ (PR)เดือนที่ 6
3ระบบที่เชื่อมข้อมูล SAP และผ่านการทดสอบ พร้อมคู่มือการใช้งานเดือนที่ 10
4ระบบขึ้นใช้งานจริง (Production) และรายงานผลการอบรมบุคลากรเดือนที่ 12

๖. เกณฑ์การตรวจรับและการวัดผล

  • ระบบทำงานได้ครบตามขอบเขตงานในข้อ ๓ และคุณสมบัติทางเทคนิคในข้อ ๔
  • คำขออนุมัติงบ (BR) และใบขอซื้อ (PR) ดำเนินการผ่านระบบได้ครบ 100% ภายใน 3 เดือนหลังเริ่มใช้งานจริง
  • จำนวนคำขอที่ถูกตีกลับเพื่อแก้ไขลดลงต่ำกว่า 30% เทียบกับกระบวนการแบบกระดาษ
  • ความพึงพอใจของผู้ใช้งานมากกว่า 80% จากแบบสอบถาม
  • ส่งมอบเอกสารคู่มือการใช้งานและจัดอบรมบุคลากรครบถ้วน

๗. งบประมาณ

วงเงินดำเนินโครงการทั้งสิ้น 24,000 บาท (สองหมื่นสี่พันบาทถ้วน) ตามรายละเอียดในข้อ ๑๐ ของเอกสารโครงการ โดยเบิกจ่ายตามงวดงานที่ส่งมอบและผ่านการตรวจรับ
